## Issues Found

### Minor — Design Issues (no TypeScript errors)

**oa-cli.ts:91** — `resolveModel` hardcodes `ollama/llama3` for ollama models:
```typescript
if (suffix === "ollama") return "ollama/llama3";
```
If the agent uses a different Ollama model (e.g., `tmux/mistral`), this hardcoded fallback silently misroutes it. Consider passing the full model ID through to `oa run` instead of mapping it.

**runtime.ts:37–46** — `AgentRuntime` interface does not include `isAvailable()`:
Both `DockerRuntime` and `OaCLIRuntime` implement an `isAvailable(): Promise<boolean>` method used by `server.ts`. This method is not part of the interface, requiring callers to use concrete class types. Acceptable as-is but worth noting if a third runtime needs to be conditionally registered.

**shared/src/types.ts** — Provider-specific model types not re-exported:
`AnthropicModel`, `OpenAIModel`, `MistralModel`, `OllamaModel`, `CLIModel`, `DockerModel` are defined in `types.ts` but not re-exported through `index.ts`. These are used internally to compose `ModelId`. No external consumers import them directly, so this is intentional.

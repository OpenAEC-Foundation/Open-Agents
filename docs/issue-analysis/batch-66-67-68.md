## Issue #66: bug(library): 14 agent templates use 'prompt' instead of 'systemPrompt', 156 missing 'tags'

**Prioriteit**: should-have
**Effort**: S (< 1 dag)
**Hetzner-relatie**: indirect
**Sprint**: Current/Sprint 13

**Analyse**:
The agent library (1177+ templates) lacks schema validation in `template_loader.py`. This results in silent failures:
- 14 templates use the incorrect field name `prompt` instead of `systemPrompt`
- 156 templates are completely missing the required `tags` field
- No validation catches these errors during load, causing silent failures or empty prompt injection
- Missing tags break filtering and discovery functionality in the UI

**Voorstel** (max 100 woorden):
Implement a JSON schema validator in `template_loader.py` that enforces required fields (`systemPrompt`, `tags`) on all templates. Execute a one-time migration: (1) rename `prompt` → `systemPrompt` in 14 affected templates, (2) add default `tags: []` to 156 templates missing this field. Add CI validation step to check all templates against schema on every commit. Consider template versioning for future schema changes.

**Blokkeert**: Better template tooling, template execution feature (#67), overall library reliability
**Geblokkeerd door**: Geen

## Issue #67: feat(cli): add 'oa run --template <name>' to execute library templates directly

**Prioriteit**: should-have
**Effort**: M (1-3 dagen)
**Hetzner-relatie**: indirect
**Sprint**: Sprint 13

**Analyse**:
The agent library contains 1177+ templates but remains documentation-only. The meta-orchestrator must manually translate template names into full `oa run` commands. Templates are stored as JSON with `systemPrompt` and `modelHint` metadata, but there is no CLI mechanism to invoke them directly. This creates friction and limits the platform's usability for automated workflows.

**Voorstel** (max 100 woorden):
Add `--template` flag to `oa run` command. CLI resolves template name (e.g., `core/iterative-planner`, `aec-blender/bonsai-ifc-loader`) to the corresponding JSON file in `agents/library/`, extracts `systemPrompt` and `modelHint` as defaults, and applies them to the agent spawn. Other flags (`--model`, `--name`) can override template defaults. Requires resolver logic, flag integration, and integration tests. Makes templates truly executable and enables workflow automation.

**Blokkeert**: Workflow automation, meta-orchestrator efficiency, platform user experience
**Geblokkeerd door**: Schema validation (#66) should be completed first for consistent template structure

## Issue #68: feat(sprint-13): Docker container isolation per agent — blocks production deployment

**Prioriteit**: critical
**Effort**: L (> 3 dagen)
**Hetzner-relatie**: direct-blocker
**Sprint**: Sprint 13

**Analyse**:
Currently, agents execute with full host permissions, making the platform unsafe for multi-user or production environments. This is a blocking issue for deployment. Sprint 13 requires implementation of Docker container isolation with:
- Container lifecycle management (`docker-runtime.ts` adapter)
- 6-layer workspace stack mounted in container volumes
- Per-agent network policies (whitelist in agent JSON config)
- Resource limits (memory, CPU, timeout) via Docker flags
- Secret injection as environment variables
- Artifact capture from containers post-execution
- Execution engine refactor to route through docker-runtime
- Convergence of safety settings (D-035) with container policies (D-040)

**Voorstel** (max 100 woorden):
Implement multi-part Docker isolation: (1) `docker-runtime.ts` adapter for container lifecycle (start, logs, cleanup); (2) workspace builder mounting D-024 6-layer stack in container; (3) network whitelist per agent config; (4) resource limits via Docker flags; (5) secret injection as env vars; (6) artifact capture post-execution; (7) refactor `runtime.execute()` to docker-runtime; (8) align safety blacklists with container policies. This is critical path for production safety.

**Blokkeert**: Production deployment, multi-user environments, regulatory compliance
**Geblokkeerd door**: Infrastructure readiness (Hetzner environment), potentially D-024 and D-035 convergence completion
